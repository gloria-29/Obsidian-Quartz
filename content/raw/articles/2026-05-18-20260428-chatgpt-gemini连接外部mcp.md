## 4. AI

能做。**但要先把话说准：Gemini 网页版目前不是一个可配置的 MCP Client**，所以不能像 Claude Desktop / Cursor / Gemini CLI 那样直接把 `NocturneMemoryMCP` 塞进网页端设置里。Google 现在正式支持 MCP 的路线主要在 **Gemini CLI**；网页端的 Connected Apps 是 Google/部分第三方 App 的产品级入口，并没有给任意自定义 MCP Server 的配置口。Gemini API 倒是支持 function calling，但那需要你自己写应用层来执行工具调用，不是直接改造 `gemini.google.com`。([Google Gemini](https://google-gemini.github.io/gemini-cli/docs/tools/mcp-server.html))

所以我的结论是：**不要强行“破解 Gemini Web 内部 MCP”，而是做一个本地 Sidecar 桥。**网页脚本负责把 Nocturne 记忆注入到 Gemini 输入框，本地 Node bridge 负责真正连接 Nocturne MCP。这样能达到你想要的效果：不用反复复述个人背景，也能把有价值的新信息写回 Nocturne，和别的 Agent 共用同一份记忆。

我给你写好了一个可跑的 starter 包：

[下载 gemini-nocturne-bridge.zip](sandbox:/mnt/data/gemini-nocturne-bridge.zip)

里面有：

`bridge.mjs`：本地 REST → MCP 桥，连接 Nocturne Memory。  
`gemini-nocturne.user.js`：Tampermonkey/Violentmonkey 油猴脚本，注入 Gemini Web。  
`.env.example`：配置 token、Nocturne 地址、默认写入父节点。  
`README.md`：运行步骤。

## 推荐实现路线

### 方案 A：最干净，但不是网页版

用 **Gemini CLI + Nocturne Memory MCP**。Gemini CLI 官方文档写明它可以发现 MCP tools、执行 tools、访问 resources，并通过 `settings.json` 的 `mcpServers` 配置连接 MCP Server。([Google Gemini](https://google-gemini.github.io/gemini-cli/docs/tools/mcp-server.html))

Nocturne Memory 自己也写了适用于 Gemini CLI 等 MCP 客户端，并提供 stdio/SSE/Streamable HTTP 方式；它的工具包括 `read_memory`、`create_memory`、`update_memory`、`delete_memory`、`add_alias`、`manage_triggers`、`search_memory`。([GitHub](https://github.com/Dataojitori/nocturne_memory))

适合：你愿意在终端或 IDE 里用 Gemini。  
不适合：你坚持使用 `gemini.google.com` 网页聊天。

### 方案 B：网页版可落地，我已经给你写了

这就是压缩包里的方案：

```text
Gemini Web
   ↓ 油猴脚本
Local Bridge: http://127.0.0.1:8787
   ↓ MCP Client SDK
Nocturne Memory MCP: http://127.0.0.1:8233/mcp
   ↓
Nocturne SQLite/PostgreSQL memory DB
```

它不是把 Gemini Web 变成“原生 MCP 客户端”，而是让 Gemini Web 每次发送前自动拿到 Nocturne 记忆：

```text
<NOCTURNE_MEMORY_CONTEXT>
system://boot
search_memory(...)
相关长期记忆...
</NOCTURNE_MEMORY_CONTEXT>

用户本轮原始输入：
...
```

然后 Gemini 就像“想起来了”一样回答。写回部分通过按钮或可选自动规则，把选中的 Gemini 回复/用户事实保存到 Nocturne 的 `create_memory`。Nocturne 的 `create_memory(parent_uri, content, priority, disclosure, title?)` 参数设计正好适合这个场景。([GitHub](https://github.com/Dataojitori/nocturne_memory/blob/main/docs/TOOLS.md))

## 运行方式

先启动 Nocturne 的 HTTP/SSE 模式。Nocturne README 写明可以用：

```bash
python backend/run_sse.py
```

默认会提供：

```text
Dashboard: http://localhost:8233/
SSE Endpoint: http://localhost:8233/sse
Streamable HTTP Endpoint: http://localhost:8233/mcp
```

这些端点是 Nocturne 文档里给出的。([GitHub](https://github.com/Dataojitori/nocturne_memory))

然后解压我给你的包：

```bash
unzip gemini-nocturne-bridge.zip
cd gemini-nocturne-bridge
cp .env.example .env
```

编辑 `.env`，至少改这个：

```env
BRIDGE_TOKEN=换成一串很长的随机字符串
```

确认 Nocturne 地址：

```env
NOCTURNE_TRANSPORT=streamable-http
NOCTURNE_MCP_URL=http://127.0.0.1:8233/mcp
NOCTURNE_PARENT_URI=core://
```

安装并启动：

```bash
npm install
npm run start
```

测试：

```bash
curl http://127.0.0.1:8787/health
curl -H "X-Bridge-Token: 你的BRIDGE_TOKEN" http://127.0.0.1:8787/tools
```

再打开 `gemini-nocturne.user.js`，改这两行：

```js
const BRIDGE_BASE = 'http://127.0.0.1:8787';
const BRIDGE_TOKEN = 'change-this-long-random-string';
```

把 `BRIDGE_TOKEN` 改成 `.env` 里的同一串。然后装进 Tampermonkey / Violentmonkey，打开：

```text
https://gemini.google.com/
```

右下角会出现一个小面板：

```text
Nocturne ↔ Gemini
🧠 注入记忆
💾 保存选中/最近回复
[ ] Enter 自动注入后发送
[ ] 自动写回“记住/偏好”等用户事实
```

第一次建议手动点 **“注入记忆”**。确认有效后，再开 **“Enter 自动注入后发送”**。

## 这个方案能做到什么

它能做到：

1. 每次发给 Gemini 前，自动读取 `system://boot`。
2. 用当前输入调用 `search_memory`，把相关 Nocturne 记忆塞进 Gemini 上下文。
3. 让 Gemini 基于你的长期记忆回答，而不是每轮从零开始。
4. 你选中 Gemini 回复后，一键写回 Nocturne。
5. 可选：当用户消息里出现“记住 / 我的偏好 / 我叫 / 纠正一下 / remember / my preference”等模式时，自动写入一条候选记忆。

它不能做到：

1. 不能让 Gemini Web 内部真正显示 “MCP tool call”。
2. 不能让 Gemini Web 原生决定调用 `read_memory` / `create_memory`。
3. 不能保证 Google 改版 DOM 后脚本永远不坏。
4. 不建议无脑自动保存所有对话，那会把 Nocturne 养成垃圾桶，坏文明。

## 安全边界

本地 bridge 默认只监听：

```text
127.0.0.1
```

而且需要：

```text
X-Bridge-Token
```

不要把它暴露到公网。也不要让任意网页都能访问它。这个 token 是为了防止别的网站偷偷请求你的本地桥，把你的私密记忆读出来。

写回记忆时，建议保持 “人工审计” 习惯。Nocturne 本来就有 Dashboard、review/audit、diff、rollback 这类能力；README 也强调 AI 写入后可以通过 Dashboard 审计和回滚。([GitHub](https://github.com/Dataojitori/nocturne_memory))

```text
core://codex         -> Codex 私有记忆
```

我按 Nocturne 现在的工具文档来写的：`read_memory` 支持读取 `system://boot` 等系统 URI，`create_memory(parent_uri, content, priority, disclosure, title?)` 用来写入新记忆，`search_memory(query, domain?, limit?)` 用来检索记忆。Nocturne 文档也说明了它支持 `NAMESPACE` / `?namespace=` / `X-Namespace` 这种原生 namespace isolation；不过我默认没有启用原生隔离，而是用了 URI 级隔离，因为这样 `core://my_user` 才能被 Gemini、Claude、Codex 真正共享。([GitHub](https://github.com/Dataojitori/nocturne_memory/blob/main/docs/TOOLS.md))

## 小模型怎么接

默认走 Ollama：

```env
EXTRACTOR_ENABLED=true
EXTRACTOR_PROVIDER=ollama
EXTRACTOR_BASE_URL=http://127.0.0.1:11434
EXTRACTOR_MODEL=qwen2.5:3b-instruct
EXTRACTOR_FALLBACK_TO_HEURISTIC=true
```

你可以这样准备：

```bash
ollama pull qwen2.5:3b-instruct
```

也可以换 OpenAI-compatible endpoint，例如 LM Studio / vLLM / llama.cpp server：

```env
EXTRACTOR_PROVIDER=openai-compatible
EXTRACTOR_OPENAI_BASE_URL=http://127.0.0.1:1234/v1
EXTRACTOR_MODEL=your-small-model
EXTRACTOR_API_KEY=
```

提取器会输出类似这种候选：

```json
{
  "kind": "preference",
  "scope": "shared_user",
  "content": "用户更喜欢中文技术解释。",
  "title": "user_prefers_chinese_tech_explanations",
  "priority": 2,
  "disclosure": "当用户的长期沟通偏好会影响回答语言或解释风格时，读取这条记忆。",
  "confidence": 0.86
}
```

然后 bridge 会自动决定写到哪里：

```text
scope=shared_user    -> core://my_user
scope=agent_private  -> core://gemini_web
scope=skip           -> 不写
```
