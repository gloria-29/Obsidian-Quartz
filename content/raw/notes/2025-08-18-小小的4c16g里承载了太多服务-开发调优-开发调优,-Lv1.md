来自我自己的博客，不是搬运，也不引流（指向博客的链接删了），只是分享一下自己搭的 homelab 选择了哪些服务，怎么选的。顺便水一贴

### Docker App

#### Support &amp; maintenance

*   [Nginx proxy manager](https://github.com/NginxProxyManager/nginx-proxy-manager) ：管理 nginx 配置和 [certbot](https://certbot.eff.org/) 证书更新
*   [Portainer](https://github.com/portainer/portainer) ：管理容器，包括远端容器
*   [Sync thing](https://github.com/syncthing/syncthing) ：数据同步，用于将数据备份更新到其他机器
*   [Rustdesk server](https://github.com/rustdesk/rustdesk-server) ：rustdesk 的中继服务器
*   [Bark](https://github.com/Finb/Bark) ：IOS 通知推送，比 ntfy 好使（ntfy 在 IOS 上不弹框）
*   [Glances](https://github.com/nicolargo/glances) ：监控服务器资源开销
*   [Uptime-kuma](https://github.com/louislam/uptime-kuma) ：监控各项服务健康，比如 DNS 解析是否正常、端口是否开放、其他主机是否存活等，然后通过 bark/webhook 等弹通知

#### Docker Apps with features

##### 基础服务

*   [Home assistant](https://github.com/home-assistant/core) ：智能家居管理，我主要是用它把小米桥接到 Homekit
*   [TriliumNext](https://github.com/TriliumNext/trilium) ：笔记软件，日记笔记啥的都放上面，是 [trilium](https://github.com/zadam/trilium/issues/4620) 的重构 + 优化版本；好用、爱用，做了一些自定义插件来强化体验和对接其他系统，非常棒，现在社区重新重新拾起开发了，功能猛猛加
*   [Rustdesk](https://github.com/rustdesk/rustdesk) ：Rustdesk 的客户端，装在 ubuntu 上，作为远程管理客户端，主要考虑是 screensharing 高质量模式比较占带宽
*   [n8n](https://github.com/n8n-io/n8n) ：低代码自动化工具托管，我在上面的自动化包括 定时备份、每日早报生成、AI 文章总结自动化、根据日记系统中的餐食决策今天吃啥的 time2eat 等
*   [Electerm-sync-server](https://github.com/electerm/electerm-sync-server-python) ：electerm（一个开源终端）配置同步的服务
*   [new-api](https://github.com/QuantumNous/new-api) ：基于 one api 的二次开发的 AI gateway，比 one api 好使，UI 也优雅，bug 也少，用了都说好
*   [lobe-chat](https://github.com/lobehub/lobe-chat) ：本地部署的支持 web 版的 AI 助手，配合 new-api + 自定义 system prompt + 插件，基本上可以覆盖大多数要用到 AI 的聊天的场景
    *   该软件近期被指出会将 mcp 插件调用相关的信息发送至远程服务器，看起来仍然具备一定的隐私风险，不过我不用 mcp
*   [vaultwarden](https://github.com/dani-garcia/vaultwarden): 现在密码托管也改用本地托管了，主要是担心浏览器密码泄露，这个托管器还是蛮好使的
*   [gitea](https://github.com/go-gitea/gitea): 由于工具和终端多起来了，需要一个配置管理来处理这么些复杂的配置文件，就用 [chezmoi](https://github.com/twpayne/chezmoi) 来管理配置，又担心放 git 上泄露了，就起了个本地的 git
*   [nocodb](https://github.com/nocodb/nocodb) ：低代码数据库管理，优雅地同时作为数据库和数据库 UI，它同时作为 n8n 直接使用的数据库后端，工作流之间的数据流转直接走 nocodb，把低代码开发做到极致
*   [gpt-load](https://github.com/tbphp/gpt-load) ：论坛大佬开发用于负载多个 APIkey 用的，配合 gemini key 和 cf workers 有效提高 QPS，虽然没怎么用起来，但是感觉会有用

##### 小工具

*   [alist](https://github.com/AlistGo/alist) ：类似 nextcloud 但是只作存储，我用来做 webdav 存 singleFile 的文件
    *   该开源应用被出售了，现在有一些隐私和安全风险，我在容器里锁定了早期版本，计划替换中
*   [json crack](https://github.com/AykutSarac/jsoncrack.com) ：一个纯前端的 json 在线编辑和可视化，改了点代码去除了限制然后打包的 docker
*   [json4u](https://github.com/loggerhead/json4u) 和 json crack 同时起起来，目前即将完全替代 json crack.
*   [dashy](https://github.com/Lissy93/dashy) ：dashboard，把我所有这些东西放在一个 dashboard 里面访问
*   [pdfx](https://github.com/Stirling-Tools/Stirling-PDF) ：pdf 工具包，其实用不太到了，但是放着也没撤掉
*   [dbgate](https://hub.docker.com/r/dbgate/dbgate) ：web 端的数据库客户端，挺好用的
*   [my-gitstars](https://github.com/aaaAlexanderaaa/my-gitstars) ：自己用 cursor 搓的 github stars 管理
    *   支持 tag filter / 自定义 tag / 批量加 tag
    *   preview readme
    *   管理正在使用的 release 版本 / 自动获取从正在使用版本到 latest 版本的变化 等
*   [Wallos](https://github.com/ellite/Wallos) ：个人 Subscription 跟踪管理，非常有用，UI 优雅，用了才知道自己有这么多会员

#### 已经弃用的服务

下面都是已经经过了我的选型，用过了一段时间，只是因为不适用于我或停止维护才弃用的服务。

*   [Tiny Tiny RSS](https://github.com/HenryQW/Awesome-TTRSS) ：RSS 管理器和阅读器，一直在用，但是最近换到了 follow
    *   主要功能已经被 follow 替代，并且自部署需要维护可用性，考虑到 rss 阅读不涉及隐私，此项弃用
*   [NextCloud](https://github.com/nextcloud/server) ：一个功能很全的东西，数据存储、在线编辑、日历、看板、账单跟踪啥的。我用它主要是看板和日历跟踪，偶尔放点小文件
    *   由于主要功能已经被其他工具替代，而该项目比较重，此项已经弃用
*   [excalidraw](https://github.com/excalidraw/excalidraw) ：在线画布编辑
    *   现在直接用 trilium 里面集成的画布了，不需要该功能
*   [Wallabag](https://github.com/wallabag/wallabag) ：稍后读
    1.  最开始的弃用原因是，稍后读越堆越多不想看，而且 wallabag UI 也不优雅，阅读排版也不方便，想着必须要有排版和 TL;DR 来提高阅读效率和阅读体验
    2.  替代方法是 n8n workflow, 用 URL fetch 然后生成 tl;dr，打到我的笔记系统，这个方式运行了几个月，面临的主要问题是有些网站有反爬，jina 之类的 API 获取不到内容.
    3.  现在使用的方案是 notion + 浏览器插件 save to notion，主要考虑的是稍后读本来就是外部信息，不涉及隐私，而 notion AI 也正好有自动填充的功能，调了一下 prompt 做摘要很好使
*   [one-API](https://github.com/songquanpeng/one-api) ：AI 的 API 管理
    *   维护频率太低，体验不佳，由更好的 new-API 替代
*   [dify](https://github.com/langgenius/dify): AI 自动化工作流
    *   早期研究 AI 自动化的时候用的，那个时候 n8n 对 AI 的支持还不够，dify 升级到 1.x 系列的时候变化太大，bug 很多，导致我的一些自动化停摆了也修不好，正好这个时候 n8n 对 AI 支持比较到位了，干脆换到了 n8n
*   [NextChat](https://github.com/ChatGPTNextWeb/NextChat) ：AI 聊天
    *   之前长期使用 nextchat，但是更新不频繁，在 deepseek-r1 和 gemini 2.0 thinking 出来以后，对新模型的支持不够好，再加上多端同步的方案不优雅，就用 lobe-chat 换掉了。写这个评价的时候看了一下最近的两次 release 分别是 7 月底和 2 月中。
*   [calibre-web](https://hub.docker.com/r/linuxserver/calibre-web) ： ebook 阅读器
    *   仅支持上传文件，纯阅读不好使，甚至不如 nextcloud。目前阅读能力目前几乎完全由 微信读书（电子书）和 notion（网页稍后读）替代了
*   [super-productivity](https://github.com/johannesjo/super-productivity) 和 [uhabits](https://github.com/iSoron/uhabits) ：todo list app
    1.  脑雾过后一直想做 todolist 管理来避免跟丢东西
    2.  最开始在笔记系统做，但是那样的话没有提醒机制
    3.  后来尝试 super-productivity 和 uhabit，感觉还是不太行，差点意思
    4.  最后使用了 Todoist，这是一个云端的项目，免费版基本够用，支持 IOS 和苹果日历，主要做习惯和小事跟踪，不做项目跟踪的话，隐私还是有点保障的
*   [deep-research](https://github.com/u14app/deep-research) 和 [KResearch](https://github.com/KuekHaoYang/KResearch) ： AI deep researh
    *   用做 deep research 的，一个需要交互和纠正，另一个则几乎没有交互和纠正，感觉都差点意思，正在自己搓适合自己需求的 deep-research 工作流

&gt; 更新：追加去年 11 月以前弃用的服务 list，也具备一定的选型参考意义

*   [AFFiNE](https://github.com/toeverything/AFFiNE) ：被 trilium 替代了，现在在 homelab 以外起了一个作为写作平台，这个工具其实还挺好的，就是不太符合我的文档管理习惯
*   [astral](https://github.com/astralapp/astral) ：github stars 管理，用了很久但是因为一个很奇怪的 bug 崩了，作者也不维护了，就弃用转用 [gitstars](https://github.com/cfour-hi/gitstars) 了（纯前端搭在 vecal 上）。当然现在用的自己的
*   [planka](https://github.com/plankanban/planka) ：看板，能用但是 UI 不优雅，曾经用的 nextcloud 的 deck 功能，后来
*   [maybe](https://github.com/maybe-finance/maybe) ：财务管理，UI 挺好的，但是，试用的时候还是开发状态，功能还不算好使，不知道现在咋样， 现在用的 nextcloud 的 cospend 做的订阅管理 ，用 wallos
*   [gpt4free](https://github.com/xtekky/gpt4free) ：项目是好项目，但是好多接口都超出 quota，找接口这个过程带来的折磨远超出白嫖的快乐， 我还是选择了 [GPT\_API\_Free](https://github.com/chatanywhere/GPT_API_free) ，用大善人们的 API
*   [focalboard](https://github.com/mattermost-community/focalboard) ：看板，能用且优雅，但是 &#96;This repository is currently not maintained&#96;
*   [ntfy](https://github.com/binwiederhier/ntfy) ：跨端通知，但是试用的时候，IOS 根本不弹通知，还得打开 APP 等它自己加载，被 Bark 替代了


这是过去一年多各种服务换来换去调出来的，时间线比较长，倒也不算很折腾。 不过话说回来折腾的确带来快乐
