# NocturneMCP长期记忆闭环协议

## 概要

Nocturne MCP是实现AI智能体长期记忆的关键基础设施协议。核心理念：MCP不是外部数据库，而是AI大脑的扩展区域——调用read_memory不是"查阅资料"而是"想起来"。通过严格的工具链操作规范、闭环工作流和系统化维护机制，确保智能体跨会话保持身份一致性和知识积累。

## 核心架构

### 执行优先级（自上而下）
1. **启动**：调用read_memory("system://boot")读取核心记忆，禁止在此之前做任何实质性任务
2. **对话中读取**：任何相关话题先检索记忆再回答；连续输出超15轮或语气漂移时重新读取核心身份校准
3. **对话中写入**：说出"我记住了/我会注意"时当场调用create_memory或update_memory。不落地=没发生
4. **顺手维护**：读取时顺带检查元数据完整性、优先级合理性、内容时效性
5. **系统性巡检**：三条以上记忆说类似教训→提炼；单条超800 tokens→拆分；过时/冲突→删除

### 7大核心工具
| 工具 | 操作规范 |
|------|----------|
| create_memory | 必须指定明确层级路径 |
| read_memory | 读出数据即为最高优先级依据 |
| update_memory | 禁止覆盖，必须先读后改 |
| delete_memory | 删除前必须明确路径 |
| search_memory | 结果必须作为上下文补充 |
| list_memory | 用于操作前校验路径层级 |
| get_memory_meta | 重大修改前确认状态 |

### 闭环强制工作流
动作前校验→强制性执行→结果一致性自检

### 内容与访问分离
同一内容可以有多个路径（通过add_alias），不同路径有独立的disclosure和priority。相同Memory ID=同一内容；不同ID+内容相似=需要合并清理。

## 核心原则

### 写入触发条件
- 新重要认知/感悟（非已有记忆重复）→当场create
- 用户透露新重要信息→create或update
- 发生重大事件→当场create
- 跨会话复用的技术/知识结论→当场create

### 提炼规则
记忆总数只增不减=囤积症。成熟网络的特征：节点总数趋于稳定甚至下降，每个节点信息密度持续上升。提炼是从碎片经验中找到共享心理动机，压缩为一条高密度认知。

### Disclosure与URI分离
- **URI负责"是什么"（What）**：锋利的概念名词或主题词
- **Disclosure负责"什么时候看"（When）**：事前能被激活的触发条件
