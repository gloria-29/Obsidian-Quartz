# DeepSeek 接入智能体后能吞下整本书了

## 概要
作者郭震分享了一个基于 DeepSeek-R1 的"吞书智能体"方案，解决大模型无法一次性处理整本长书的问题。通过 Trae IDE + MCP 协议 + pdf-reader 智能体的组合，实现逐章节自动提取和总结，全程免费、本地运行、不需要写代码。以 338 页的《强化学习》教材为测试，约 10 分钟完成全书 15 章的摘要。

## 核心内容

### 问题背景
- DeepSeek 原生不支持一次处理几百页的电子书，只能处理前 30% 左右
- 根本原因：Transformer 输入长度受限 + 注意力计算复杂度 O(n²)，超长文本导致计算和显存爆炸
- 即使号称百万/两百万上下文的大模型，也采用稀疏注意力、分块、局部聚焦等优化，实际精度会打折

### 解决方案：吞书智能体
- **工具选择**：Trae IDE（字节开发，免费使用），对 MCP 智能体支持最好且做了深度优化
- **模型**：内置 DeepSeek-R1（128K 上下文），免费使用
- **核心组件**：pdf-reader MCP Server（开源），提供 `read_pdf_text`、`read_by_orc`、`read_pdf_images` 三个工具
- **编排方式**：自定义提示词（迭代 20+ 次），指导智能体逐章节处理，每章上下文控制在模型长度限制内

### 操作步骤
1. 安装 Trae IDE 并打开新建文件夹
2. 选择 DeepSeek-R1 模型，点击 @智能体 → 创建智能体
3. 配置智能体提示词（PDF 章节提取与总结自动化处理流程）
4. 添加 pdf-reader MCP Server（手动配置 JSON，指向本地代码目录）
5. 导入电子书 PDF，智能体自动逐章处理

### 方案特点
- **精度无损**：每章单独处理，不依赖长上下文压缩
- **自动输出**：生成 HTML 总结页面 + 每章独立 txt 文件，自动提取起止页码
- **可扩展**：即使 1000 页的书也能应对
- **已知缺陷**：模型思考次数达上限时需手动输入"继续"

## 关键概念
- **MCP 协议**：Model Context Protocol，让 AI 模型调用外部工具的标准协议
- **Trae IDE**：字节跳动开发的 AI 编程 IDE，内置多种免费模型
- **吞书智能体**：作者命名的方案，指能完整处理一本书的 AI 智能体
- **pdf-reader MCP Server**：作者编写的开源工具，支持 PDF 文本提取、OCR 和图片读取
