# LLM Knowledge Wiki：Karpathy 的知识编译方法论

## 概要

Andrej Karpathy 分享的个人知识库构建工作流：将 LLM 从"一次性回答工具"转变为"知识持续累积与合成引擎"。以 Obsidian 为界面、LLM 为"程序员"、Markdown Wiki 为"代码库"，通过自动编译、链接、维护实现知识的复合增长。该方法引发社区广泛实践，成为 2026 年 AI 知识管理的标志性范式。

## 核心内容

### 三层架构

| 层级 | 角色 | 说明 |
|------|------|------|
| Raw 来源层 | 唯一事实来源 | 文章、论文、播客转录等原始文件，只读不可变 |
| Wiki 层 | LLM 完全拥有 | 摘要页、实体页、主题综述、比较表格、索引、反向链接 |
| Schema 层 | 规则文件 | CLAUDE.md / SCHEMA.md，定义结构、命名、更新流程 |

### 构建流程

1. **工具准备**：Obsidian（免费，Graph View + Marp + Dataview）+ LLM Agent（Claude Code / Cursor / OpenCode）
2. **数据摄入**：Obsidian Web Clipper 保存网页 → raw/ 目录 → LLM 阅读提取 → 创建/更新摘要、概念、实体页、反向链接
3. **查询输出**：Wiki 达到一定规模后（~100 篇、40 万字），LLM 可处理复杂合成问答，输出 Markdown/Marp 幻灯片/图表
4. **健康检查**：定期 LLM 运行 linting，发现不一致、补全缺失、挖掘新连接、清理冗余，防止幻觉固化
5. **知识飞轮**：优秀输出归档回 Wiki，实现持续生长

### 核心范式转变

- **从 RAG 到编译**：传统 RAG 每次查询临时检索；LLM Wiki 在写入时就将知识"编译"为持久链接的结构化文件
- **知识复合增长**：每次新增内容都会更新现有页面，知识在持续积累中自我生长

- **本地隐私**：Elephas、Ollama + Obsidian 插件

## 关键概念

- **知识编译**：LLM 在写入时将原始资料转化为结构化、相互链接的 Markdown 文件，而非查询时临时检索
- **Schema 驱动**：通过规则文件定义 Wiki 的目录结构、命名规范、更新流程，人与 LLM 共同迭代
- **健康检查（Linting）**：定期让 LLM 审查数据一致性、补全缺失、挖掘新连接，是防止幻觉固化的关键机制
- **知识飞轮**：输出重新输入系统，形成"编译 → 查询 → 输出 → 归档"的持续增长循环
