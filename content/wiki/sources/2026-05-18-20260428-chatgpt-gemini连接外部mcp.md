# Gemini 连接外部 MCP：网页版桥接 Nocturne 记忆方案

## 概要

探讨如何让 Gemini 网页版连接外部 MCP 服务器（以 Nocturne Memory 为例），实现跨 Agent 记忆共享。Gemini Web 原生不支持 MCP 配置，但可通过油猴脚本 + 本地 Node Bridge 的 Sidecar 模式实现记忆自动注入与回写。

## 核心内容

### 问题背景

Gemini 网页版（gemini.google.com）不是可配置的 MCP 客户端，无法像 Claude Desktop 或 Gemini CLI 那样直接接入自定义 MCP Server。Google 官方 MCP 支持主要在 Gemini CLI 侧。

### 方案对比

| 方案 | 路径 | 适用场景 |
|------|------|----------|
| 方案 A：Gemini CLI + MCP | CLI `settings.json` 配置 `mcpServers` | 愿意在终端使用 Gemini |
| 方案 B：网页 Sidecar 桥 | 油猴脚本 + 本地 Bridge + MCP Client SDK | 坚持使用 gemini.google.com |

### 方案 B 架构

```
Gemini Web → 油猴脚本 → Local Bridge (127.0.0.1:8787) → MCP Client SDK → Nocturne Memory MCP (127.0.0.1:8233)
```

每次发送前自动注入 `<NOCTURNE_MEMORY_CONTEXT>` 到 prompt，让 Gemini 基于长期记忆回答。

### 升级功能（v4）

- **小模型记忆提取器**：接入 Ollama/LM Studio 等本地小模型（如 qwen2.5:3b），自动判断哪些内容值得长期保存，过滤一次性任务和敏感信息
- **Agent Namespace 路由**：`core://my_user`（共享）、`core://gemini_web`、`core://claude`、`core://codex`（各自私有）
- 置信度阈值 `EXTRACTOR_MIN_CONFIDENCE=0.65`，防止垃圾记忆污染

### 安全边界

- Bridge 仅监听 `127.0.0.1`，需 `X-Bridge-Token` 认证
- 写回记忆建议保持人工审计，Nocturne 提供 Dashboard 审计与回滚

## 关键概念

- **Sidecar 桥模式**：不改造宿主应用，通过注入脚本 + 本地代理实现功能扩展
- **记忆注入**：在用户输入前自动拼接长期记忆上下文，避免重复复述
- **Agent Namespace 隔离**：按 Agent 划分记忆空间，同时支持共享用户记忆层
- **记忆提取器**：小模型作为过滤层，只保存高置信度的长期事实
